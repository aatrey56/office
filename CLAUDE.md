# office mod — working notes for Claude

A Claude Code plugin ("mod") made of TypeScript function hooks. The owner runs several Claude
sessions at once; this mod is their command centre. Branch `build/office-scene` holds all recent
work (not yet merged to `main`).

## What it does
- `/office`: one pane, two views (`t` toggles).
  - **Text board:** live sessions on this Mac; message them (`m`), copy a resume command (`c`).
  - **Pixel office:** a Game Boy Color–style room per git project (`h`/`l` switch). Each session
    is a character in the room for its state and activity: coding (computer desk), reviewing (plain
    desk), planning (whiteboard), idle (couch, music notes), needs-you (meeting chairs, "!"). Office
    workers walk in, report to the manager, and leave.
  - Under the picture: crew list (`1`–`9`), a chat window of the selected session (`u`/`n` scroll),
    and a message box (`m`). `d` toggles a debug line; `b` opens manga.
- `/office band|pane`: the board as a strip above the prompt, or back in the pane.
- `/office manage` / `manage off`: makes this session the manager of its git project (a
  `prompt.compose` section with the role); other sessions there are told to report to it. Shared
  project notebook: `post_note` / `read_notes` (`~/.claude/office/notes/<project>.md`).
- Jobs: `/spawn` (workers via `claude --bg`), `/route-task`, `/route-eval` (scores the router
  against `evals/routing.jsonl`), `/codex-review`, `/jobs`. Router: Jev → Claude → rules.
  Budget guard on worker starts: only small tasks from 80% (5-hour) / 85% (week), nothing at 95%
  unless the person types `/spawn --force`. Tools: `session_usage`, `list_sessions`,
  `message_session`, `route_task`, `spawn_worker`, `codex_review`, `codex_exec`.
- `/manga`: reader pane (Ghostty only), `~/Manga/<Series>/<chapter>`, `.cbz` cached; keys `j`/`k` page,
  `h`/`l` chapter, `o` office tab, `Esc` close.

## Layout of the code
- `hooks/register.tsx` installs: `board.tsx`, `jobs.tsx`, `manage.tsx`, `manga.tsx`, `scene.tsx`.
- Pure (no `$`) and unit-tested: `sessions.ts`, `router.ts`, `spawn.ts`, `codex.ts`, `evals.ts`,
  `budget.ts`, `manager.ts`, `scene/{model,motion,paint,encode,art}.ts`.
- `scene/art-data.ts` is GENERATED by `~/Coding/office-art` (`bun tools/export.ts [--debug]`):
  room placements and layers in `tools/room.ts`, seats/door in `tools/export.ts`, cut list and
  palettes in `tools/art.ts`, crew looks in `tools/crew.ts`. `--debug` writes `out/debug.png`
  (grid, blocked cells, seat arrows) and `out/preview.png` (everyone seated) — look at them.
- `types/index.d.ts`: every shared type and the declared `$.state` keys. `docs/build-plan.md` is
  the design (partly out of date). `CREDITS.md`: art sources (furniture sheet has no formal
  license — personal use only).

## Rules that bit us (follow them)
- **`$` never crosses an import** (the validator refuses it). Keep pure logic in pure files.
- **Button hotkeys are one digit or one lowercase letter.** `[` `]` made the whole scene fail.
- **Type-check with** `npx -y -p typescript tsc -p . --pretty false` and read the EXIT CODE.
  Grepping coloured tsc output reports 0 errors falsely.
- **Live images:** inline `{ png }` frames were accepted but never replaced on screen; frames go
  through files with a rising `generation` (`~/Library/Caches/office-scene`).
- **Timers** (`$.clock.every`) die on reload; every redraw restarts them (self-healing).
- **Floor plan:** every seat must be reachable from the door; the export refuses otherwise, and a
  test walks the real map.
- **Draw order:** furniture and crew are sorted by bottom pixel; seats have `dx`/`dy`/`zBias`.
- **Snapshot test** (`motion.test.ts`): a hash of the empty room. After a deliberate art or
  layout change, re-export, look at `out/debug.png`, then update the hash.
- **Workers share one folder.** Give parallel workers separate files.

## Checks before every commit
`npx -y -p typescript tsc -p . --pretty false` (exit 0) · `claude plugin validate .` ·
`claude plugin test .` (84 tests). Commit messages end with the Co-Authored-By line the session gives.

## How the owner works (respect this)
- **Lean tests:** one per main behaviour, safety rules, and real regressions only. No speculative
  edge cases or formatting tests.
- **Visual changes:** render and look at the result yourself (debug/preview PNGs, or a headless
  settle-and-paint script) BEFORE asking the owner to check. The owner verifies live only after.
- **Explanations:** plain and short. Sometimes asked for ASD-STE100 Simplified Technical English.
- Don't copy things to the clipboard unless asked. Effort is capped at high unless asked.
- After a mod change, the owner's watching session needs `/reload-plugins`.
- Priority note: the owner is preparing for data-engineering/SWE interviews; `/route-eval` numbers
  have the most interview value. Timebox polish.
